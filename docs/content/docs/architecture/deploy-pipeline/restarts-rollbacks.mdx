| | <Term id="restart">Restart</Term> | <Term id="rollback">Rollback</Term> |
|---|---|---|
| Image | Of the live deploy | Of an earlier deploy |
| Settings, limits, environment | The current ones | The current ones |
| Rule | The engine finds the live deploy when the restart runs, not when it enters the queue. | The target was live: its status is `live` or `deactivated`. Its image must still exist (see `--keep-images`). |

## Why the restart rule matters

A restart that waits in the queue behind another deploy does not undo that deploy. It restarts the new live deploy.

A restart is how a change of variables reaches the containers that run.

For the user view, see [Restart a service](/docs/concepts/deploys/restarts) and [Roll back](/docs/concepts/deploys/rollbacks).
