After the <Term id="health-check" /> passes, the deploy cannot go back. A [cancel](/docs/architecture/deploy-pipeline/cancel) after the switch gets a refusal.

## The order matters

The engine marks the deploy `live` before it stops the old instances. If the server stops during the drain, it comes back with the new deploy.

The change of routes and the wait of 2 seconds apply to web services and static sites. Other services have no route.
