## All the tasks

| Task | When | What it does |
|---|---|---|
| <Term id="deploy-worker">Deploy workers</Term> | One per service that has deploys in the queue | Each worker runs the deploys of its service one at a time, in order. The server builds 2 images at a time (`--build-concurrency`). See [Deploy pipeline](/docs/architecture/deploy-pipeline). |
| <Term id="reconciler">Reconciler</Term> | At boot, each 10 seconds, and after scale, suspend and resume | It makes the containers and the routes agree with the store. See [Reconciler](/docs/architecture/reconciler). |
| <Term id="route-watcher">Route watcher</Term> | Each second | It follows the host ports of the instances. Thus the routes follow a container that Docker restarted on a new port. |
| <Term id="oom-watcher">OOM watcher</Term> | On each Docker `oom` event | It logs each container of this server that the kernel killed because of its memory limit. See [OOM watcher](/docs/architecture/reconciler/oom-watcher). |
| Cron scheduler | About each 15 seconds | It starts the runs of the <Term id="cron-job">cron jobs</Term> whose schedule is due (UTC). It skips the runs that the server missed while it was down. |
| <Term id="change-feed">Change-feed</Term> detector | Each second, only while a client listens | It compares the store and sends what changed. |
| TLS manager | With `--https-addr` and `--acme-email` | It requests <Term id="certificate">certificates</Term> for the public hosts. It renews those that expire in less than 30 days. |
