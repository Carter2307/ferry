## The list

- **One administrator account.** No other users, teams, roles or audit log exist. Each API token has the same access. See [What a token can do](/docs/architecture/security/token-access).
- **No encryption at rest.** Ferry stores secrets in plain text in `ferry.db`. See [The data directory](/docs/architecture/security/data-directory).
- **No IP allow lists.** The only rate limits are the [connection limits](/docs/architecture/security/proxy-limits) and the [limit on failed sign-ins](/docs/architecture/security/sign-in-limit), which is for the full server.
- **Gaps in the limits.** Builds have no memory limit and no CPU limit. Disks have no quotas. Disk and network I/O have no limit. Each container can reach each service and datastore on the private network. See [What Ferry does not contain](/docs/architecture/security/not-contained).
- **No private registry.** Docker must pull each image with no login. Ferry does not support the credentials of a private <Term id="registry" />.
