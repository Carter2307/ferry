Without these rules, a second `ferryd` would see the containers of the first server as <Term id="orphan">orphans</Term> and remove them.

In a server, the engine lists and touches only the containers with the label `ferry.instance=<prefix>`.

## The two rules

| Rule | How `ferryd` applies it |
|---|---|
| One process per data directory | It holds an exclusive lock on `<data-dir>/ferryd.lock` while it runs. |
| One data directory per <Term id="name-prefix" /> | It records the owner of its prefix (`--name-prefix`, default `ferry`) on the <Term id="marker-volume" /> `<prefix>-owner`. The labels of the volume are the `instance_id` and the path of the data directory. |

## What a refusal looks like

```text title="ferryd" noCopy
another ferryd is already running with data directory …
```

```text title="ferryd" noCopy
Error: Docker resources with prefix 'ferry' belong to another Ferry server (data dir /var/lib/ferry). Run this server with a different --name-prefix, stop the other server, or pass --take-over to adopt the resources (the other server's containers will then be managed — and possibly removed — by this one).
```

## Run more than one server

Give each server its own `--name-prefix` and its own `--data-dir`. See [Multiple servers](/docs/guides/multiple-servers).
