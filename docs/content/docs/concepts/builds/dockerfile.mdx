Ferry uses your <Term id="dockerfile" /> when the runtime is `docker`. It also uses it when the runtime is `auto` and the <Term id="root-directory" /> has a `Dockerfile`.

```text title="Deploy log" noCopy
==> Using Dockerfile at ./Dockerfile
```

## The rules

| Subject | Rule |
|---|---|
| Path | `--dockerfile` sets a path from the root directory. The default is `Dockerfile`. |
| Context | The <Term id="build-context" /> is the root directory. Your `.dockerignore` applies. |
| Start command | If the service has a <Term id="start-command" />, it replaces the `CMD` of the image. Ferry runs it with `/bin/sh -c`. |
| Port | The port setting, a `PORT` variable, or the one port that the image `EXPOSE`s. If there is none, set `--port`. See [The port of your app](/docs/concepts/deploys/ports). |
| Variables | Your build gets them as secrets and as build arguments. See [Secrets in a build](/docs/concepts/builds/build-secrets). |

<Accordions>
  <Accordion title="A Dockerfile above the root directory">
    The path can point above the root directory, for example `../Dockerfile`. It must stay in the repository.
  </Accordion>
</Accordions>
