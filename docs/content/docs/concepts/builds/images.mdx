## The tag of an image

Each build makes an image with the <Term id="image-tag" /> `<prefix>/<service>:<deploy-id>`. Ferry also puts a label on it, to know its service.

## What Ferry keeps

- The 5 newest images of the service. `--keep-images` on <Term id="ferryd" /> sets this number.
- The image of the live deploy, at any age.
- The images of the deploys in progress, at any age.

## If the image of a deploy is gone

You cannot [roll back](/docs/concepts/deploys/rollbacks) to that deploy. Deploy again from the source.

A <Term id="rollback" /> and a <Term id="restart" /> use the images that Ferry keeps.

<Accordions>
  <Accordion title="What Ferry never deletes">
    Ferry deletes only the images that it gave a tag to for the service. It never deletes an image that you pulled, or a public base image.
  </Accordion>
  <Accordion title="Services that deploy an image">
    Ferry pulls the image, then gives it the same form of tag. This is the <Term id="pinned-image" />. Thus each deploy refers to the exact image that it ran.
  </Accordion>
  <Accordion title="When you delete a service">
    Ferry deletes all its images.
  </Accordion>
</Accordions>
