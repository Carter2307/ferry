---
title: Roll back
description: A rollback is a new deploy that uses the image of an earlier deploy.
---

```bash title="Terminal"
ferry rollback api dep-3493c505ea9b4415b359 --follow
```

In the dashboard, open **Deploys**. In the menu of a deploy, choose **Roll back to this deploy**.

## The rules

- You can roll back to a deploy with the status `live` or `deactivated`. A failed or canceled deploy was never live: you cannot roll back to it.
- A rollback gives you the old **code**. The instances start with the **current** settings and variables.
- Ferry keeps the 5 newest images of each service, and the live image.

<Accordions>
  <Accordion title="If the image is gone">
    Ferry removes older images (`--keep-images` on `ferryd` sets the number). Then the rollback fails with the cause. Deploy from the source again.

    Ferry removes only the tags that it made. It does not delete a public image that you pulled.
  </Accordion>
  <Accordion title="Images from a registry">
    Ferry pins the image of each deploy with its own tag: `<prefix>/<service>:<deploy-id>`. A rollback runs the exact image of that deploy, even if the tag in the registry moved.
  </Accordion>
  <Accordion title="API">
    [`POST /api/v1/services/{id}/rollback`](/docs/reference/api/services#roll-back-to-an-earlier-deploy)
  </Accordion>
</Accordions>
