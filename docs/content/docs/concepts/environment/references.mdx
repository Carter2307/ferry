A value can contain a <Term id="reference" />: `${{kind.name.property}}`. Ferry resolves it each time a <Term id="container" /> starts. Thus an app always gets the current host, port or password.

## The three parts

| Part | Meaning | Example |
|---|---|---|
| `kind` | `datastore` or `service` | `datastore` |
| `name` | The name of the <Term id="datastore" /> or the <Term id="service" /> | `app-db` |
| `property` | What you want from it | `connectionString` |

See the properties of a [datastore](/docs/concepts/environment/datastore-properties) and of a [service](/docs/concepts/environment/service-properties).

## Use references

```bash title="Terminal"
ferry env set api \
  'DATABASE_URL=${{datastore.app-db.connectionString}}' \
  'REDIS_URL=${{datastore.cache.connectionString}}' \
  'SEARCH_URL=${{service.search.internalUrl}}/v1'
```

The [reference syntax page](/docs/reference/env-references) has the full grammar.

<Accordions>
  <Accordion title="Write a literal ${{">
    To write a literal `${{`, escape it as `$${{`. The value `$${{ not.a.ref }}` reaches the app as `${{ not.a.ref }}`.
  </Accordion>
  <Accordion title="References in a build">
    References also reach <Term id="build">builds</Term>: Ferry gives the variables to the build with their references resolved. If Ferry cannot resolve a reference yet, it leaves the variable out of the build. The build log has a warning.
  </Accordion>
</Accordions>
