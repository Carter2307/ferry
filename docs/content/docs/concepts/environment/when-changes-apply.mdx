Ferry freezes the environment of a <Term id="deploy" /> when the deploy starts its instances. This is the <Term id="snapshot" />.

All that starts containers for that deploy later uses the snapshot: crash replacements, [scaling](/docs/concepts/scaling), a resume, and [jobs](/docs/concepts/jobs). Thus a saved change applies only at the next deploy or <Term id="restart" />.

## What Ferry does after a change

`ferry env set`, `ferry env unset` and the API with `restart=true` restart the service only if it has something to restart.

| State of the service | Result |
|---|---|
| Live | Ferry puts a restart in the queue (<Term id="trigger" /> `env_change`). |
| A deploy in progress | The restart waits in the queue behind it. Thus you do not lose the new values. |
| Never deployed | Nothing restarts. The first deploy uses the new values. |
| Suspended | Nothing restarts. After `ferry resume`, run `ferry restart NAME` to apply the change. |

  <Accordion title="If the restart fails">

  </Accordion>
  <Accordion title="More about restarts and snapshots">
    A restart is a new deploy that uses the live image again with the current settings and environment. See [Restart a service](/docs/concepts/deploys/restarts) and [Settings and the live deploy](/docs/concepts/deploys/snapshot).
  </Accordion>
