A <Term id="job-run" /> uses the <Term id="snapshot" /> of the <Term id="live-deploy" />. This is true for a <Term id="one-off-job" /> and for a <Term id="cron-job" />.

## What the container gets

| Part | Value |
|---|---|
| Image | The image of the live deploy |
| Variables | The variables of the live deploy, without `PORT`: a job listens on no port |
| Limits | The memory and CPU limits of the live deploy |
| Network | The [private network](/docs/concepts/networking), with no published port |
| Restart | None |
| Disk | A one-off job gets the [disk of the service](/docs/concepts/jobs/disk) |

## After a change of settings

A change of settings, limits or variables after the live deploy does not apply to a run.

If the job needs the new values, restart the service first.

```bash title="Terminal"
ferry restart api --follow
```
