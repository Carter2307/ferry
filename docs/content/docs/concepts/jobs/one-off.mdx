---
title: Run a one-off job
description: ferry run starts one new container of a service, runs your command in it, then removes it.
---

Write the command after `--`. With `--follow`, the <Term id="cli" /> shows the output. If the job fails, the CLI exits with 1.

A <Term id="one-off-job" /> runs next to the <Term id="instance">instances</Term> of the service, not in them.

## The rules

- The service needs a <Term id="live-deploy" />.
- A suspended service cannot run a job.
- The job uses the same image, variables and limits as the live deploy. See [What a run uses](/docs/concepts/jobs/container).

<Accordions>
  <Accordion title="How Ferry runs the command">
    The command runs with `sh -c` in the container.

    - One argument after `--` is a line for the <Term id="shell" /> of the container. Thus the shell reads `'npm run a && npm run b'` and `'echo $HOME'`.
    - Ferry quotes each argument when there is more than one.

    ```bash title="Terminal"
    ferry run api -- 'python manage.py shell -c "print(1)"'
    ```
  </Accordion>
  <Accordion title="If the job uses too much memory">
    The system stops a run that goes over its memory limit. The run fails, and there is no restart.

    ```text title="Job log" noCopy
    ==> Job failed: the job ran out of memory (limit 512 MiB) — raise the service's memory limit
    ```

    Raise the limit of the service with `ferry update NAME --memory …`. Then run `ferry restart NAME`.
  </Accordion>
  <Accordion title="CLI and API">
    [`ferry run`](/docs/reference/cli#ferry-run) has all the options of `ferry run` and `ferry jobs`.

    `POST /api/v1/services/{id}/jobs` with `{"command": "…"}` starts a run. For a cron job, the command is optional. See [Jobs](/docs/reference/api/jobs) in the API reference.
  </Accordion>
</Accordions>
