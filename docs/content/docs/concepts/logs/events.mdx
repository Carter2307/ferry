The <Term id="change-feed" /> reports each change to services, deploys, datastores, env groups and job runs. It sends one <Term id="event" /> for each change. The dashboard uses it to stay up to date. You can use it for your own automation.

## Listen to the feed

  lines={[

## The events

| Event | Meaning |
|---|---|
| `ready` | The feed is on. Get your data after it: the feed reports each later change. |
| `change` | Something changed. The event tells what changed, not the new value. Get the resource to read its new state. |

| Field of `change` | Values |
|---|---|
| `kind` | `service`, `deploy`, `datastore`, `env_group` or `job` |
| `action` | `created`, `updated` or `deleted` |
| `service_id` | Set for services, deploys and jobs |

<Accordions>
  <Accordion title="If your client is too slow">
    A client that is too far behind gets `{"kind":"all","id":"*","service_id":null,"action":"resync"}`. Then get all your data again.
  </Accordion>
  <Accordion title="Which changes, and how fast">
    - The feed reports a change from the API, from a webhook and from Ferry.
    - The changes from Ferry are the progress of a deploy, the creation of a datastore and cron runs.
    - While a client listens, the server compares its database each second. It also compares after each write from the API or a webhook. Thus a change arrives in about one second.
  </Accordion>
