A <Term id="custom-domain" /> is one more <Term id="hostname" /> for one <Term id="web-service" /> or <Term id="static-site" />. The <Term id="proxy" /> routes it when you add it. No deploy is necessary.

## The rules

- The domain must be a valid DNS name with one dot or more. It cannot be an <Term id="ip-address" />.
- Ferry stores it in lower case, with no dot at the end.
- A domain belongs to one service.
- It cannot be the default host of a service: `<name>.<domain>` under a domain of the server.
- It cannot be the dashboard host.
- Point the DNS of the domain at your server. Use an `A`/`AAAA` <Term id="dns-record">record</Term>, or a `CNAME` to a name that resolves to it.

## Add a custom domain

<Tabs items={['CLI', 'API', 'Blueprint']} groupId="interface" persist>
<Tab value="CLI">

```bash title="Terminal"
ferry domains add shop shop.example.com
# Added shop.example.com. Point its DNS (A/AAAA or CNAME) at this server.
ferry domains shop            # list
ferry domains rm shop shop.example.com
```

</Tab>
<Tab value="API">

```bash title="Terminal"
curl -X POST http://127.0.0.1:7878/api/v1/services/shop/domains \
  -H "Authorization: Bearer $FERRY_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"domain": "shop.example.com"}'
```

</Tab>
<Tab value="Blueprint">

```yaml title="ferry.yaml"
services:
  - type: web
    name: shop
    domains: [shop.example.com, www.example.com]
```

</Tab>
</Tabs>

For the complete procedure, follow [Custom domains & HTTPS](/docs/guides/custom-domains-https).
