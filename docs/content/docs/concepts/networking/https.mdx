Ferry gets each <Term id="certificate" /> from <Term id="lets-encrypt" />, or from a different <Term id="acme" /> <Term id="certificate-authority">CA</Term>. It uses the <Term id="http-01" />.

## Turn it on

```bash title="Terminal"
ferryd --base-domain apps.example.com \
  --proxy-addr 0.0.0.0:80 --https-addr 0.0.0.0:443 \
  --acme-email you@example.com
```

The two options `--https-addr` and `--acme-email` are necessary. `--https-addr` alone does not start an <Term id="https" /> listener.

- The HTTP listener must be reachable from the internet on port 80.
- The DNS name must point at the server.

<Callout type="warning" title="Use port 443">
With HTTPS on, Ferry prints public URLs as `https://host` with no port. Listen on `0.0.0.0:443`. Then these URLs work.
</Callout>

## Which hosts get a certificate

Each host that the proxy routes, but not a <Term id="local-name" /> and not an IP address:

- the host of each web service and static site, under each domain of the server
- each custom domain
- the dashboard host, if you set one

Each host gets its own certificate. Ferry does not request wildcard certificates.

<Accordions>
  <Accordion title="A different certificate authority">
    - `--acme-staging` uses the staging environment of Let's Encrypt: untrusted certificates, generous rate limits.
    - `--acme-directory` points at a different ACME CA.
    - When you change the CA, Ferry replaces the certificates of the previous CA.

    See each option on [Server options](/docs/reference/server-options). For a full server, follow [Production setup](/docs/guides/production).
  </Accordion>
</Accordions>
