A <Term id="service" /> can have more than one <Term id="instance" />. Then the <Term id="proxy" /> shares the requests between them. This is <Term id="load-balancing" />.

The rule is <Term id="round-robin" />: each instance gets a request in its turn.

## The rules

- A route points only at instances that accept <Term id="tcp">TCP connections</Term>.
- A `GET` or `HEAD` request with no body cannot reach an instance: the proxy tries it one more time on a different instance.
- The proxy does not try other requests again.
- During a <Term id="deploy" />, the proxy moves to the new instances in one step, after they pass their <Term id="health-check" />. See [Deploys](/docs/concepts/deploys).
