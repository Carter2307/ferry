Ferry makes one Docker <Term id="bridge-network" /> for each server. Its name is the name prefix: `ferry` by default. This is the <Term id="private-network" />. Each <Term id="container" /> of the server joins it: service instances, one-off <Term id="job">jobs</Term>, <Term id="cron-job">cron jobs</Term> and datastores.

Each service <Term id="instance" /> gets a DNS <Term id="alias" /> equal to the name of the service. Each <Term id="datastore" /> gets an alias equal to its name.

## Call a service by its name

```bash
curl http://api:3000/health        # a private service named "api" listening on 3000
psql postgresql://…@app-db:5432/…  # a datastore named "app-db"
```

Do not write hosts and ports in your code. Use a <Term id="reference" /> ([References](/docs/concepts/environment/references)): `${{service.api.hostport}}` becomes `api:3000` when the service starts.

## Private services

A <Term id="private-service" /> is reachable only here. It also needs a <Term id="port" />: Ferry finds it the same way as for a web service. `ferry show NAME` prints it as the internal address.

```text title="ferry show api (excerpt)" noCopy
Internal address:  api:3000
```

<Callout type="warning" title="No isolation between services">
All services of one server share this network. Ferry does not isolate the services from each other on it.
</Callout>
