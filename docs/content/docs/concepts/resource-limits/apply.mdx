A deploy or a restart saves the limits in its <Term id="snapshot" />, with the image, the environment and the command. All that starts a container later uses the live snapshot.

## Apply a new limit

A restart is sufficient. It uses the live image again and builds nothing.

```bash title="Terminal"
ferry update api --memory 2G
ferry restart api --follow
```

The deploy log shows the limits of the new instances.

```text title="Deploy log (excerpt)" noCopy
==> Using port 10000 (default port)
==> Limits: 2 GiB memory, 1 CPU per instance
==> Starting 1 instance(s)
```

<Accordions>
  <Accordion title="Who uses the live snapshot">
    - A scale and a resume.
    - The [reconciler](/docs/concepts/self-healing), when it replaces a crashed instance.
    - One-off jobs and cron runs.
  </Accordion>
  <Accordion title="Special cases">
    - For a cron job, the deploy log says `per run`, not `per instance`.
    - A blueprint apply restarts each live service whose limits changed. You do not have to restart them.
    - The limits of a datastore apply immediately. See [Set the limits of a datastore](/docs/concepts/resource-limits/datastore).
  </Accordion>
</Accordions>
