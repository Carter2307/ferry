Ferry puts five guards around each <Term id="container" /> that it starts. Each guard has a default value.

## The defaults

| Guard | Default | Set with |
|---|---|---|
| [Memory](/docs/concepts/resource-limits/memory) | 512 MiB | The service or the datastore. If not set: `--default-memory-limit` |
| [CPU](/docs/concepts/resource-limits/cpu) | 1 CPU | The service or the datastore. If not set: `--default-cpu-limit` |
| [Processes](/docs/concepts/resource-limits/processes) | 1024 | `--pids-limit` |
| [Logs](/docs/concepts/resource-limits/log-rotation) | 10 MiB × 3 files | `--log-max-size`, `--log-max-files` |
| [Free disk](/docs/concepts/resource-limits/free-disk) | 1 GiB free | `--min-free-disk` |

The flags are options of `ferryd`. See [Server defaults](/docs/concepts/resource-limits/defaults).

## A limit is for one container

Containers do not share a limit. A <Term id="service" /> with 3 <Term id="instance">instances</Term> can use 3 times its limit, plus the limit of each job that runs.

A limit is a cap. It does not reserve memory or CPU. Ferry does not make sure that all the limits together fit on the server.
