A limit is a cap, not a reservation. This is <Term id="overcommit" />: all the limits together can be larger than the memory of the server.

On Linux, `ferryd` lowers its own <Term id="oom-score" /> when it starts. The default is `-500`.

## Set the score

| Flag of `ferryd` | Default |
|---|---|
| `--oom-score-adj` | `-500` |

`ferryd` does not raise a lower value that exists, such as `OOMScoreAdjust=-900` from systemd.

<Accordions>
  <Accordion title="If ferryd cannot lower its score">
    `ferryd` needs root or `CAP_SYS_RESOURCE` to lower the score. Without them, it writes a warning in its log.

    Then set `OOMScoreAdjust=` in the systemd unit of `ferryd`. See [Production setup](/docs/guides/production). Add `--oom-score-adj 0` to stop the warning.
  </Accordion>
  <Accordion title="Processes that ferryd starts">
    `ferryd` starts git and the docker CLI with a score of 0. Thus the kernel can stop a `git` that uses too much memory. Containers do not get the score of `ferryd`.
  </Accordion>
  <Accordion title="Other systems">
    On a system that is not Linux, the flag does nothing.
  </Accordion>
</Accordions>
