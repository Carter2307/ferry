Two containers must not write to one <Term id="disk" /> at the same time. Thus a service with a disk has exactly 1 <Term id="instance" />. Ferry refuses to scale it higher.

Each <Term id="deploy" /> and each <Term id="restart" /> stops the old instance, then starts the new instance. There is no <Term id="zero-downtime" /> for this service.

## In the deploy log

```text title="Deploy log" noCopy
==> Mounting disk at /data
==> Limits: 512 MiB memory, 1 CPU per instance
==> Stopping 1 old instance(s) first (services with a disk are redeployed in place)
==> Starting 1 instance(s)
```

A service with no disk does the opposite: the new instance starts first. See [The steps of a deploy](/docs/concepts/deploys/steps).
