<Term id="scaling">Scaling</Term> changes the number of <Term id="instance">instances</Term> of a service. A <Term id="web-service" />, a <Term id="static-site" />, a <Term id="private-service" /> or a <Term id="worker" /> runs 1 instance by default. The maximum is 50.

The <Term id="snapshot" /> has the image, the variables, the command and the limits of the live deploy. Settings, limits or variables that you changed after the last deploy do not apply to the new instances. To apply them, [restart the service](/docs/concepts/scaling/restart).

## Set the number at creation

```bash title="Terminal"
ferry create api --repo https://github.com/you/api --instances 2   # at creation
```

<Accordions>
  <Accordion title="What you cannot scale">
    - A <Term id="cron-job" />: each run starts its own container.
    - A service with a [disk](/docs/concepts/scaling/disk-deploys): it has exactly 1 instance.
    - Below 1 instance. To stop a service, [suspend](/docs/concepts/scaling/suspend) it.
  </Accordion>
  <Accordion title="During a deploy">
    Ferry saves the new number. Ferry applies it immediately after the deploy.
  </Accordion>
  <Accordion title="API">
    ```bash title="Terminal"
    curl -X POST http://127.0.0.1:7878/api/v1/services/api/scale \
      -H "Authorization: Bearer $FERRY_TOKEN" \
      -H 'Content-Type: application/json' \
      -d '{"instances": 3}'
    ```

    `PATCH /api/v1/services/api` with `{"instances": 3}` does the same. See [Scale a service](/docs/reference/api/services#scale-a-service).
  </Accordion>
</Accordions>
