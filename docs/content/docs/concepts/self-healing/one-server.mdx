## The lock of the data directory

While it runs, `ferryd` holds an exclusive lock on `<data-dir>/ferryd.lock`. A second server with the same <Term id="data-directory" /> refuses to start.

```text title="Error" noCopy
Error: another ferryd is already running with data directory /var/lib/ferry
```

## The owner of the name prefix

All Docker resources of a server have its <Term id="name-prefix" />: `--name-prefix`, default `ferry`. One prefix has one data directory as its owner.

```text title="Error" noCopy
Error: Docker resources with prefix 'ferry' belong to another Ferry server (data dir /var/lib/ferry). Run this server with a different --name-prefix, stop the other server, or pass --take-over to adopt the resources (the other server's containers will then be managed — and possibly removed — by this one).
```

<Callout type="warning" title="--take-over">
Use `--take-over` only if you want this server to control the resources. An example: you restored a data directory without its `instance_id` file.
</Callout>

<Accordions>
  <Accordion title="Why the prefix has an owner">
    The reconciler removes each container with its prefix that it sees as an orphan. Two servers with the same prefix would remove the containers of each other.

    Ferry records the owner on a marker volume: `<prefix>-owner`.
  </Accordion>
  <Accordion title="Which servers refuse to start">
    - A server whose data directory does not own the prefix.
    - A server with an empty data directory that finds containers with its prefix.

    See [Multiple servers](/docs/guides/multiple-servers).
  </Accordion>
</Accordions>
