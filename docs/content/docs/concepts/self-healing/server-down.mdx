<Term id="ferryd" /> controls Docker, but it is not your apps. When it stops, Docker continues to run each <Term id="container" />.

## While ferryd is down

| Thing | State |
|---|---|
| Containers of services and datastores | They run |
| The [private network](/docs/concepts/networking) | It works |
| Public traffic | Stopped: no <Term id="proxy" /> |
| Schedules of each <Term id="cron-job" /> | Stopped. Ferry skips the runs that it did not start. It does not run them later. |
| Deploys | Stopped |

## After that

When `ferryd` starts, it repairs the state. See [When ferryd starts again](/docs/concepts/self-healing/server-start).

To make systemd start `ferryd` after a crash or a reboot, see [Production setup](/docs/guides/production).
