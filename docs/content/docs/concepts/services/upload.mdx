A service with no repository and no image deploys an <Term id="upload" />.

## Upload a folder

```bash title="Terminal"
ferry up my-app              # packs ., creates my-app if needed, uploads and deploys
ferry up my-app --dir ./app  # another directory
```

## What goes into the archive

| Files | In the <Term id="archive" /> |
|---|---|
| Files that `.gitignore`, `.ignore` or `.ferryignore` exclude | No |
| `.git`, `node_modules`, `target`, `.venv`, `venv`, `__pycache__`, Python virtualenvs | Never |
| Hidden files such as `.env.example` or `.npmrc` | Yes |
| <Term id="symlink">Symlinks</Term> that point outside the directory | No, with a warning |

<Accordions>
  <Accordion title="The ignore files">
    `ferry up` follows `.gitignore` also outside a git repository. `.ferryignore` wins over the other <Term id="ignore-file">ignore files</Term>. Thus a `!pattern` line in `.ferryignore` adds a file that git ignores.
  </Accordion>
  <Accordion title="A manual deploy">
    `ferry deploy my-app`, or **Manual deploy** in the dashboard, builds the newest upload again.
  </Accordion>
  <Accordion title="ferry up on a git or image service">
    `ferry up` also works on a service that has a repository or an image. That deploy builds your local files and tells you so.
  </Accordion>
  <Accordion title="Size limits">
    The archive can be 512 MiB at most. For the limits on the server, see [Limits](/docs/concepts/builds/limits).
  </Accordion>
</Accordions>
