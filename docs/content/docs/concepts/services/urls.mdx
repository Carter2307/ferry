A web service or a static site gets a <Term id="public-url" />. The <Term id="default-domain" /> is the <Term id="base-domain" /> until you [connect a domain](/docs/guides/domains) of your own.

## Examples

| Server settings | URL of a service named `api` |
|---|---|
| Defaults (`--base-domain localhost`, proxy on `:8080`) | `http://api.localhost:8080` |
| `--base-domain apps.example.com --proxy-addr 0.0.0.0:80` | `http://api.apps.example.com` |
| Same, with HTTPS (`--https-addr` and `--acme-email`) | `https://api.apps.example.com` |

The URL has no port when the port is 80 or when HTTPS is on.

## More hostnames

Each domain of the server serves the service. If you connect `example.com` to the server, the service also answers at `api.example.com`.

A <Term id="custom-domain" /> is for one service:

```bash title="Terminal"
ferry domains add api api.example.org
```

The proxy sends all these hostnames to the service. See [Networking, domains & TLS](/docs/concepts/networking).

    `--public-port` changes the port that Ferry shows in URLs. An example: a router forwards a different port to the proxy.
  </Accordion>
  <Accordion title="Why the default URLs work with no DNS setup">
    Browsers resolve `*.localhost` to your own machine.
  </Accordion>
