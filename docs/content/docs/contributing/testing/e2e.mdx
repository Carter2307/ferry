A test of this type is a <Term id="gated-test" />.

## Run all the suites

```bash title="Terminal"
cargo build -p ferryd                  # the CLI suite drives a real ferryd binary
FERRY_E2E=1 cargo test --workspace
```

<Callout type="warning" title="Use a Docker daemon that you can share">
The tests create containers, volumes, networks and images. They pull small public images and bind free local ports.

They never touch the resources of a Ferry server, because each test uses its own <Term id="name-prefix" />. But run them where this load is acceptable.
</Callout>

## Run one suite

Give the crate and the name of the test.

```bash title="Terminal"
FERRY_E2E=1 cargo test -p ferry-engine --test e2e
FERRY_E2E=1 cargo test -p ferry-build --test build_e2e
```

[The suites](/docs/contributing/testing/e2e-suites) lists each name.

<Accordions>
  <Accordion title="Where the CLI suite finds ferryd">
    The CLI suite looks for `ferryd` in the variable `FERRY_E2E_FERRYD`. Without the variable, it looks next to the test binary. For a debug test run, this is `target/debug/ferryd`.

    Thus you run `cargo build -p ferryd` first.
  </Accordion>
</Accordions>
