## What each part shows

| Part | Content |
|---|---|
| Info tiles | Status, instances that run, private address (`name:port`), source, latest deploy, runtime, domains and creation date. |
| Graph | The env groups that the service links. The datastores and services that its variables reference, for example `app-db` with the label `via DATABASE_URL`. |
| **Instances** | The live CPU and memory of each <Term id="container" />, next to its limits. The **Scale** button changes the number of instances. |
| **Service availability** | Manual deploy (with a **Clear build cache** option), restart, scale, run a one-off job, suspend or resume. |

## If an instance used too much memory

The system stops an <Term id="instance" /> that goes above its memory limit. This is an <Term id="oom" />.

The instance gets an **OOM killed** badge with its exit code. The **Raise the limit** link opens **Settings** → **Resources**. See [Resource limits](/docs/concepts/resource-limits).
