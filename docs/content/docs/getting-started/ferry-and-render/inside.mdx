## The parts of ferryd

| Part | Work |
|---|---|
| `ferry-proxy` | The public <Term id="proxy" />: routes by <Term id="host-header" />, and <Term id="tls" /> |
| `ferry-api` | REST, <Term id="sse" /> and webhooks, for the dashboard and the CLI |
| `ferry-engine` | Deploys, the <Term id="reconciler" />, cron and datastores |
| `ferry-build` | `git` and `docker build` |
| <Term id="sqlite" /> | The <Term id="desired-state" />, in `ferry.db` |

## What the engine does

- **A deploy.** The <Term id="engine" /> clones the repository, or unpacks an upload. It detects the runtime and builds an image.
- **The switch.** The engine starts new containers next to the old containers and tests their health. Then it moves the proxy to them in one step. It drains and stops the old containers. See [The steps of a deploy](/docs/concepts/deploys/steps).
- **A repair.** The reconciler replaces each container that crashed. It also keeps the number of instances correct and updates the routes.

Read more in [Architecture](/docs/architecture/overview).
