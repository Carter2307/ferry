| Not in Ferry v1 | What it is |
|---|---|
| Multiple nodes | More than one server for the same apps |
| <Term id="autoscaling">Autoscaling</Term> | The host changes the number of instances when the load changes |
| <Term id="pr-preview">Pull request previews</Term> | A temporary copy of the app for each pull request |
| Private registry authentication | A login to pull an image from a private <Term id="registry" /> |
| <Term id="secret-file">Secret files</Term> | A file with secret text in the container |
| <Term id="ip-allow-list">IP allow lists</Term> | Only the addresses on the list can connect |
| Teams, or <Term id="rbac" /> | More than one user, each with a role |

## What Ferry has

- One server runs all your apps.
- Environment variables and env groups hold your secret values.
- A Ferry server has one administrator account. It has no other users.
- You set the number of instances by hand:

```bash title="Terminal"
ferry scale api 2
```
