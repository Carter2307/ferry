| Render feature | In Ferry |
|---|---|
| Environment variables, environment groups | Yes. Ferry does not have secret files. |
| Private network (`service-name:port`) | Yes: a Docker <Term id="bridge-network" /> with DNS <Term id="alias">aliases</Term> |
| Custom domains, free TLS | Yes: <Term id="lets-encrypt" /> (<Term id="acme" /> <Term id="http-01" />) |
| Manual scaling | Yes: the instances are behind <Term id="round-robin" /> <Term id="load-balancing" /> in the proxy |
| Instance types (`plan`) | Yes: [memory and CPU limits](/docs/concepts/resource-limits) for each service and datastore. The server defaults are 512 MiB and 1 CPU for each container. Ferry changes the <Term id="render-plan" /> of a blueprint into limits. |
| Logs (build and runtime, live tail), basic metrics | Yes: <Term id="sse" /> streams. CPU and memory of each instance, next to its limits. Ferry flags each <Term id="oom" />. |
| Dashboard, CLI, REST API | Yes |
