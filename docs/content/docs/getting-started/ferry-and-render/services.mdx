| Render feature | In Ferry |
|---|---|
| Web services, private services, background workers, cron jobs, static sites | Yes, all five [service types](/docs/concepts/services) |
| Native runtimes (Node, Python, Go, Rust, Ruby, static) and Dockerfiles | Yes: Ferry detects the <Term id="runtime" /> and writes the <Term id="dockerfile" /> |
| A prebuilt Docker <Term id="image" /> | Yes (`--image`) |
| Managed Postgres, Key Value (Redis) | Yes: containers with <Term id="volume">volumes</Term>, internal and external URLs |
| Persistent <Term id="disk">disks</Term> | Yes: a named volume. A service with a disk has 1 instance. A deploy stops the old instance first. |
| <Term id="one-off-job">One-off jobs</Term> | Yes (`ferry run`) |
| <Term id="blueprint">Blueprints</Term> (`render.yaml`) | Yes: `ferry blueprint apply`, the same schema (a subset) |

## Example: a service from an image

```bash title="Terminal"
ferry create hello --image nginx:alpine --port 80
```

Read more: [Builds & runtimes](/docs/concepts/builds), [Datastores](/docs/concepts/datastores), [Jobs](/docs/concepts/jobs) and the [blueprint reference](/docs/reference/blueprint).
