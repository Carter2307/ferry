This page takes you from a running server to a deployed app in a few commands. You deploy `examples/node-hello`, a tiny Node.js web service from the Ferry repository, straight from your disk: no git repository, no Dockerfile.

You need `ferryd` and `ferry` built, as described in [Installation](/docs/getting-started/installation). The output below comes from a real run; ids, times and ports will differ on your machine.

<Steps>
<Step>
### Start the server

From the root of the Ferry repository:

```bash title="Terminal"
ferryd
```

It starts the server in the background and prints the dashboard URL and the API token:

```text title="Output" noCopy
  Ferry 0.1.0 is running in the background (pid 48213)
  Dashboard + API : http://127.0.0.1:7878
  Dashboard (proxy): http://ferry.localhost:8080
  Apps            : http://<name>.localhost:8080
  …
  API token       : fy_3f9c…

  Log in with:  ferry login --server http://127.0.0.1:7878 --token fy_3f9c…

  Logs            : ferryd logs -f
  Stop            : ferryd stop
```

The server keeps running while you use the same terminal for the next steps.
</Step>

<Step>
### Log in with the CLI

Copy the `ferry login` command that `ferryd` printed:

```bash title="Terminal"
ferry login --server http://127.0.0.1:7878 --token <token printed by ferryd>
```

```text title="Output" noCopy
Logged in to http://127.0.0.1:7878 (Ferry 0.1.0)
Saved to /home/you/.config/ferry/config.json
```

`ferry login` checks the URL and the token against the server, then saves them so later commands don't need them. The token is also in `ferry-data/api_token`. More in [Set up the CLI](/docs/getting-started/cli).
</Step>

<Step>
### Deploy the app

```bash title="Terminal"
cd examples/node-hello
ferry up --follow
```

[`ferry up`](/docs/reference/cli#ferry-up) packs the current directory, creates a web service named after it (`node-hello`), uploads the archive and deploys it. `--follow` streams the build and deploy log until the app is live:

```text title="Output" noCopy
Packing /home/you/ferry/examples/node-hello …
Packed 2 file(s), 576 B
Created web service 'node-hello' (srv-8593a88388f349feade2)
Uploading 576 B …
Deploy dep-3493c505ea9b4415b359 queued (upload), streaming logs…
09:36:21 ==> Starting deploy dep-3493c505ea9b4415b359 (trigger: upload)
09:36:21 ==> Extracting uploaded source archive
09:36:21 ==> Extracted 2 files (791 B)
09:36:21 ==> Detected Node.js runtime
09:36:21 ==> Generated Dockerfile.ferry for the Node.js runtime
09:36:21 ==> Building image ferry/node-hello:dep-3493c505ea9b4415b359
09:36:21 #1 [internal] load build definition from Dockerfile.ferry
…
09:36:21 ==> Build successful 🎉
09:36:21 ==> Using port 10000 (default port)
09:36:21 ==> Limits: 512 MiB memory, 1 CPU per instance
09:36:21 ==> Starting 1 instance(s)
09:36:21 ==> Started instance 82e2be (port 10000, published on 127.0.0.1:62694)
09:36:21 ==> Waiting for 1 instance(s) to become healthy: the port must accept TCP connections (timeout 120s)
09:36:21 [82e2be] > node-hello@1.0.0 start
09:36:21 [82e2be] > node server.js
09:36:22 [82e2be] node-hello listening on :10000
09:36:23 ==> Health check passed
09:36:23 ==> Routing traffic to the new instance(s)
09:36:23 ==> Your service is live 🎉
09:36:23 ==> Available at http://node-hello.localhost:8080
Deploy dep-3493c505ea9b4415b359 is live at http://node-hello.localhost:8080
```

Here is what happened:

- There is no Dockerfile, so Ferry **detected the runtime** from `package.json` and generated a Dockerfile for Node.js (`node:22-alpine`, `npm install`, then `npm start`). See [Builds & runtimes](/docs/concepts/builds).
- The app doesn't set a port, so Ferry picked the **default port 10000** and passed it in the `PORT` variable, which `server.js` reads.
- The container got the server's default **resource limits**: 512 MiB of memory and 1 CPU (the `Limits` line). See [Resource limits](/docs/concepts/resource-limits).
- Ferry started the new container, waited until its port accepted connections, then **routed traffic** to it. See [Deploys](/docs/concepts/deploys).

The first deploy takes longer: Docker downloads the `node:22-alpine` base image once.
</Step>

<Step>
### Open the app

The service answers on its own hostname through the Ferry proxy:

```bash title="Terminal"
curl http://node-hello.localhost:8080
```

```text title="Output" noCopy
Hello from Ferry (node)! service=node-hello deploy=dep-3493c505ea9b4415b359
```

Or open http://node-hello.localhost:8080 in your browser. `ferry open node-hello` prints the URL and tries to open it for you.
</Step>

<Step>
### Look at it

List your services, then check the running instances and their logs:

```bash title="Terminal"
ferry services
ferry status node-hello
ferry logs node-hello
```

```text title="Output" noCopy
NAME         TYPE   STATE   INSTANCES   URL                                LAST DEPLOY
node-hello   web    live    1           http://node-hello.localhost:8080   live · 8s ago

node-hello: live — 1/1 instance(s) running
INSTANCE   DEPLOY     STATE     PORT    CPU            MEMORY                 RESTARTS   STARTED
82e2be     4415b359   running   62694   4.7% / 1 CPU   24.2 MiB / 512.0 MiB   0          8s ago

09:36:21 [82e2be] > node-hello@1.0.0 start
09:36:21 [82e2be] > node server.js
09:36:22 [82e2be] node-hello listening on :10000
```

`ferry status` shows each instance's CPU and memory use next to its limits (`4.7% / 1 CPU`). Add `-f` to `ferry logs` to keep streaming new lines; press <kbd>Ctrl</kbd>+<kbd>C</kbd> to stop. Each line shows the time and the instance it came from.

The same service is on the dashboard at http://127.0.0.1:7878: sign in with the API token, then open **node-hello**. See the [Dashboard tour](/docs/getting-started/dashboard).
</Step>

<Step>
### Change the code and redeploy

Edit the greeting in `server.js`, then run the same command again:

```js title="server.js"
res.end(`Hello from Ferry (node)! service=…`); // [!code --]
res.end(`Hello again from Ferry! service=…`); // [!code ++]
```

```bash title="Terminal"
ferry up --follow
```

```text title="Output" noCopy
Packing /home/you/ferry/examples/node-hello …
Packed 2 file(s), 581 B
Uploading 581 B …
Deploy dep-ba5a7fce730d4061aaa7 queued (upload), streaming logs…
09:36:39 ==> Starting deploy dep-ba5a7fce730d4061aaa7 (trigger: upload)
…
09:36:40 ==> Started instance e5725a (port 10000, published on 127.0.0.1:62742)
09:36:40 ==> Waiting for 1 instance(s) to become healthy: the port must accept TCP connections (timeout 120s)
09:36:40 [e5725a] node-hello listening on :10000
09:36:41 ==> Health check passed
09:36:41 ==> Routing traffic to the new instance(s)
09:36:43 ==> Stopping 1 old instance(s)
09:36:43 ==> Your service is live 🎉
09:36:43 ==> Available at http://node-hello.localhost:8080
Deploy dep-ba5a7fce730d4061aaa7 is live at http://node-hello.localhost:8080
```

The service already exists, so `ferry up` only uploads and deploys. The old container kept serving until the new one passed its health check; then the proxy switched to the new one and the old one was stopped. That's a zero-downtime, blue/green deploy.

```bash title="Terminal"
curl http://node-hello.localhost:8080
# Hello again from Ferry! service=node-hello deploy=dep-ba5a7fce730d4061aaa7
```
</Step>

<Step>
### Roll back

Every deploy is kept in the service's history:

```bash title="Terminal"
ferry deploys node-hello
```

```text title="Output" noCopy
ID                         STATUS        TRIGGER   COMMIT   CREATED   DURATION
dep-ba5a7fce730d4061aaa7   live          upload    -        5s ago    1s
dep-3493c505ea9b4415b359   deactivated   upload    -        23s ago   2s
```

Roll back to the first deploy with [`ferry rollback`](/docs/reference/cli#ferry-rollback). Ferry reuses the image that deploy built, so nothing is rebuilt:

```bash title="Terminal"
ferry rollback node-hello dep-3493c505ea9b4415b359 --follow
```

```text title="Output" noCopy
Deploy dep-16d99450e6984bb18843 queued (rollback), streaming logs…
09:36:49 ==> Rolling back to deploy dep-3493c505ea9b4415b359 (deploy dep-16d99450e6984bb18843)
09:36:49 ==> Reusing image ferry/node-hello:dep-3493c505ea9b4415b359 of deploy dep-3493c505ea9b4415b359
09:36:49 ==> Using port 10000 (default port)
09:36:49 ==> Limits: 512 MiB memory, 1 CPU per instance
09:36:49 ==> Starting 1 instance(s)
…
09:36:51 ==> Health check passed
09:36:51 ==> Routing traffic to the new instance(s)
09:36:53 ==> Stopping 1 old instance(s)
09:36:53 ==> Your service is live 🎉
Deploy dep-16d99450e6984bb18843 is live at http://node-hello.localhost:8080
```

A rollback is a new deploy with the trigger `rollback`, so it shows up at the top of `ferry deploys` and can itself be rolled back.
</Step>

<Step>
### Clean up

Delete the service with its containers, images and deploy history:

```bash title="Terminal"
ferry delete node-hello
```

```text title="Output" noCopy
Delete service 'node-hello' with all its deploys? [y/N] y
Deleted service 'node-hello'
```

Pass `--yes` to skip the question, for example in scripts. Stop the server with `ferryd stop` when you are done.
</Step>
</Steps>

## When a deploy fails

A deploy that fails never replaces the version that is live. Try it with a start command that crashes:

```bash title="Terminal"
ferry up --start-cmd "node crash.js" --follow
```

```text title="Output" noCopy
Updated 'node-hello': start command
…
09:37:33 [d1c6b8] Error: Cannot find module '/app/crash.js'
…
09:37:34 ==> Removing 1 new instance(s)
09:37:34 ==> Deploy failed: instance d1c6b8 crashed (exit code 1)
Deploy dep-ca4bc7b5862742959b70 failed (deploy_failed): instance d1c6b8 crashed (exit code 1)
```

The command exits with code 1, and the previous deploy keeps serving. When an instance crashes during the health check, the log also shows its last 50 lines of output. Clear the setting and deploy again:

```bash title="Terminal"
ferry up --start-cmd "" --follow
```

For other errors, such as a health check that times out or a port that is already taken, see [Troubleshooting](/docs/guides/troubleshooting).

## Deploy other things

`ferry up` works for any directory Ferry can build. A few variations:

```bash title="Terminal"
# A static site: the directory is served by nginx as it is
ferry up my-site --dir ./public --type static

# A service from a git repository, with 2 instances and an HTTP health check
ferry create api --repo https://github.com/you/api --branch main --instances 2 --health /healthz --follow

# A prebuilt image
ferry create hello --image nginx:alpine --port 80

# A cron job that runs every night at 03:00 UTC
ferry create nightly --type cron --image busybox:stable --schedule "0 3 * * *" --start-cmd 'echo hello'
```
