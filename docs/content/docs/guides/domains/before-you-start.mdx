| You need | How |
|---|---|
| Control of the <Term id="dns" /> of the domain | At your <Term id="registrar" /> or your <Term id="dns-provider" />. |
| <Term id="port">Port</Term> 80 open to the internet | Start <Term id="ferryd" /> with `--proxy-addr 0.0.0.0:80`. |
| For <Term id="https" />: port 443 and an email | Start `ferryd` with `--https-addr 0.0.0.0:443` and `--acme-email`. |

Without the two HTTPS options, the domain works over HTTP only. See [Production setup](/docs/guides/production).

A <Term id="subdomain" /> works too: `apps.example.com` gives `<service>.apps.example.com`.

<Callout type="warning" title="On a public server without --base-domain, turn the dashboard host off">
With the default base domain (`localhost`), the public <Term id="proxy" /> also answers for the host `ferry.localhost`. That host is the dashboard and the API.

On a laptop, this is useful. On a server that the internet can reach, start `ferryd` with `--dashboard-host none`. As an alternative, give it your own hostname with HTTPS. See [Security model](/docs/architecture/security).
</Callout>
