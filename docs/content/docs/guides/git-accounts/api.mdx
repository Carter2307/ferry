title: Connect with the API
description: A script connects an account with an access token, then lists repositories and branches.
---

```bash title="Connect an account with a token"
curl -s -X POST http://127.0.0.1:7878/api/v1/git/connections \
  -H "Authorization: Bearer $FERRY_TOKEN" -H 'Content-Type: application/json' \
  -d '{"provider": "github", "token": "<access token>"}'
```

The <Term id="dashboard" /> uses the [git endpoints of the API](/docs/reference/api/git). A script uses an <Term id="access-token" />, because no person is there to click on the page of the provider.

## List, then create a service

```bash title="List its repositories, the branches of one, then create a service"
curl -s -H "Authorization: Bearer $FERRY_TOKEN" \
  http://127.0.0.1:7878/api/v1/git/connections/git-4db07471b4a74da2a889/repositories

curl -s -G -H "Authorization: Bearer $FERRY_TOKEN" \
  http://127.0.0.1:7878/api/v1/git/branches \
  --data-urlencode 'repo_url=https://github.com/you/api.git'
# {"default_branch":"main","branches":["main","develop"],"connection_id":"git-4db07471b4a74da2a889"}

curl -s -X POST http://127.0.0.1:7878/api/v1/services \
  -H "Authorization: Bearer $FERRY_TOKEN" -H 'Content-Type: application/json' \
  -d '{"name": "api", "repo_url": "https://github.com/you/api.git", "branch": "main"}'
```

The service names no connection. Its `repo_url` is on github.com. Thus Ferry <Term id="clone">clones</Term> it with the account that you connected there.

`ferry create --repo …` and [blueprints](/docs/reference/blueprint) work the same way.

<Accordions>
  <Accordion title="A self-hosted provider">
    Add `"base_url": "https://gitlab.example.com"` when you connect.
  </Accordion>
  <Accordion title="How the branch list works">
    `GET /api/v1/git/branches` reads the branches from the repository itself (`git ls-remote`), the same way a deploy clones it. It works for each URL that a service can deploy from.
  </Accordion>
  <Accordion title="Your own client of the browser flow">
    1. Call `POST /api/v1/git/authorize` with a `redirect_uri`. The answer has the page to open. `method: post` means: submit a form with `fields`.
    2. The provider sends the browser back to `redirect_uri`. Give its query parameters to `POST /api/v1/git/callback`.
    3. Do these steps again while the `status` of the answer is `redirect`.
  </Accordion>
</Accordions>
