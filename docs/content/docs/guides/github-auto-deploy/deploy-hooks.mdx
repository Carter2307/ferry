A <Term id="deploy-hook" /> is a secret URL that deploys one service when you call it. Use it from your <Term id="ci" />, or from each tool that can send an HTTP request. The server needs no webhook secret for it.

## Call the hook

<Terminal
  lines={[
    '$ ferry deploy-hook show api',
    'https://ferry.apps.example.com/hooks/deploy/srv-5c57d756f6ad47f59800?key=652f4935c8534c02aad20d953d8a7ff1',
    "$ curl -X POST 'https://ferry.apps.example.com/hooks/deploy/srv-5c57d756f6ad47f59800?key=652f4935c8534c02aad20d953d8a7ff1'",
  ]}
/>

## The rules

- `POST` and `GET` work. The answer is `202`, with a summary of the deploy in the queue (<Term id="trigger" /> `deploy_hook`).
- The hook deploys the source in the settings of the service: the head of its <Term id="branch" />, its <Term id="image" />, or its last upload. It cannot choose a <Term id="commit" />.
- The URL is the secret. Store it as a secret of your CI.
- `ferry deploy-hook rotate api` replaces the key. The old URL stops immediately.
- The printed URL starts with the server URL of your CLI. From outside, call it on your public dashboard host.

<Accordions>
  <Accordion title="Errors">
    An unknown service id and a wrong key get the same answer: `401`. Thus nobody can use the hook to find services. A suspended service answers `409`.
  </Accordion>
  <Accordion title="Images">
    If the image has the tag `latest` or no tag, Ferry pulls it again.
  </Accordion>
