## A connected account

[Connect your GitHub account](/docs/guides/git-accounts) to the server. You authorize it on a page of GitHub. This makes a <Term id="git-connection" />.

Then Ferry <Term id="clone">clones</Term> the repositories of the account with the account. This applies to each method that creates a service. The URL has no credentials.

## HTTPS with a token

Put a GitHub personal <Term id="access-token" /> in the URL. The token needs read access to the contents of the <Term id="repository" />.

```text title="Repository URL" noCopy
https://USERNAME:TOKEN@github.com/you/api
```

Ferry keeps the credentials out of the build logs and the error messages. It gives them to git through the environment, not through the command line.

## SSH

Use the SSH URL. Give the user that runs `ferryd` an SSH key that GitHub accepts, for example a deploy key.

```text title="Repository URL" noCopy
git@github.com:you/api.git
```

Git runs in batch mode. It accepts the host key at the first connection.
