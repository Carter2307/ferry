| Subject | On Ferry |
|---|---|
| Language versions | They come from your project files, not from variables. See [Language guides](/docs/guides/language-guides). |
| Pre-deploy commands | They do not exist. Run <Term id="migration">migrations</Term> with a <Term id="one-off-job" />: `ferry run NAME -- npm run migrate`. See [Deploy an app with Postgres](/docs/guides/postgres-app). |
| Plans and regions | A plan is limits, not a machine. Regions do not apply: each service runs on your server. See [Resource limits](/docs/concepts/resource-limits). |
| Key value stores | Ferry ignores `maxmemoryPolicy`. A full Redis refuses writes. |
| The port | The same as Render: Ferry sets `PORT` (default `10000`) and routes to it. |
| Static sites | <Term id="nginx" /> serves them with `try_files $uri $uri/ $uri.html` and your `404.html`. Ferry does not support `routes` (redirects and rewrites) and `headers`. |

## Not in Ferry

<Term id="pr-preview">Pull request previews</Term>, <Term id="autoscaling" />, private <Term id="registry" /> credentials, <Term id="secret-file">secret files</Term> and <Term id="ip-allow-list">IP allow lists</Term>.

<Accordions>
  <Accordion title="Where the language version comes from">
    - Node: `engines.node` in `package.json`.
    - Python: `.python-version` or `runtime.txt`.
    - Go: the `go` line of `go.mod`.
    - Ruby: `.ruby-version` or the `Gemfile`.

    Ferry gives the variables `NODE_VERSION` and `PYTHON_VERSION` to your app like all other variables.
  </Accordion>
  <Accordion title="The limits of a plan">
    The limits are a ceiling, not a reservation. Nothing makes sure that they fit the server. Ferry lowers a CPU limit that is above the number of CPUs of the server to that number. Choose a server that is large enough for what you run.
  </Accordion>
  <Accordion title="The memory of a key value store">
    Ferry sets the <Term id="maxmemory" /> of Redis to 3/4 of the memory limit of the store. Give a cache enough memory with its `plan` or `memoryLimit`.
  </Accordion>
</Accordions>
