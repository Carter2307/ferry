<Steps>
<Step>

### Stop the writes on Render

Stop the writes while you copy, or plan a short maintenance period.

</Step>
<Step>

### Write the Render database into a file

```bash title="Terminal"
docker run --rm postgres:16-alpine pg_dump --no-owner --no-acl "$RENDER_EXTERNAL_DATABASE_URL" > shop.sql
```

<Term id="pg-dump" /> runs from an <Term id="image" />. Use an image that is as new as the <Term id="postgres" /> version of the Render server, or newer.

</Step>
<Step>

### Find the user and the database

```bash title="Terminal"
ferry db show shop-db    # prints the Database and User to load into
```

</Step>
<Step>

### Load the file into the Ferry datastore

```bash title="Terminal"
docker exec -i ferry-ds-shop-db psql -U shop_db shop_db < shop.sql
```

<Term id="psql" /> runs in the <Term id="container" /> of the <Term id="datastore" />. Replace `shop_db` with the `User` and the `Database` that `ferry db show` prints.

</Step>
</Steps>

<Accordions>
  <Accordion title="Where the names come from">
    - The name of the container is `<prefix>-ds-<name>`: `ferry-ds-shop-db` with the default prefix.
    - The user and the database come from `user` and `databaseName` in your `render.yaml`.
    - Without these keys, the two get the name of the datastore, with `_` in the place of `-`. Here, it is `shop_db`.
  </Accordion>
  <Accordion title="Redis">
    Ferry has no import tool for Redis. A key value store starts empty.
  </Accordion>
</Accordions>
