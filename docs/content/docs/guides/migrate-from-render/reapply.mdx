The result lists each resource as `create`, `update` or `unchanged`. Ferry deletes nothing: a resource that you remove from the file stays on the server.

## What Ferry does for each change

| Change in the file | Ferry |
|---|---|
| Build or deploy settings of a service | Deploys the service again. |
| Only the limits (`plan`, `memoryLimit`, `cpuLimit`) or the variables of a service | <Term id="restart">Restarts</Term> the service, if it is live. Ferry builds nothing. |
| No `plan`, `memoryLimit` or `cpuLimit` in the file | Keeps the limits, like `numInstances`. |
| Version, database name or user of a <Term id="datastore" /> | Keeps the old values and shows a warning. |
| Limits of a datastore | Changes them in place, without a restart. |

## Preview first

```bash title="Terminal"
ferry blueprint apply render.yaml --dry-run
```

The <Term id="dry-run" /> shows all these changes and changes nothing. It also shows limit changes, such as `memory_limit: 512 MiB → 2 GiB`.
