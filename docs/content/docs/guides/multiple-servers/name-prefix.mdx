The <Term id="name-prefix" /> (default `ferry`) is part of each Docker name and <Term id="container-label" /> that a server creates.

## The names

| Resource | Name |
|---|---|
| Private network | `<prefix>` |
| Service containers | `<prefix>-<service>-<deploy>-<random>` |
| Job containers | `<prefix>-job-<service>-<job>` |
| Datastore containers and volumes | `<prefix>-ds-<name>`, `<prefix>-ds-<name>-data` |
| Service disks | `<prefix>-svc-<service id>-disk` |
| Built images | `<prefix>/<service>:<deploy id>` |
| Ownership marker volume | `<prefix>-owner` |

Each container also has the label `ferry.instance=<prefix>`.

## Why two servers must never share a prefix

The <Term id="reconciler" /> of a server removes the containers under its prefix that it does not know. Such a container is an <Term id="orphan" />. With the same prefix, each server deletes the apps of the other. See [Self-healing](/docs/concepts/self-healing).

## What different prefixes give you

The servers stay apart. They have different networks, thus their services cannot call each other by name. They also have different images and volumes.
