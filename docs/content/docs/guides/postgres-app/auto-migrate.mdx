## Way 1: a job after each deploy

```bash title="Terminal"
ferry up notes --follow && ferry run notes --follow -- npm run migrate
```

For a service that deploys from git, use `ferry deploy notes --follow` as the first command.

With `--follow`, the first command fails if the deploy fails. Thus the <Term id="job" /> runs only on the <Term id="image" /> that is now live.

## Way 2: a migration when the app starts

```bash title="Terminal"
ferry update notes --start-cmd 'npm run migrate && npm start'
```

Each <Term id="instance" /> runs the <Term id="migration" /> when it starts. Thus the migration must be safe to run more than one time, and at the same time.

Use `CREATE TABLE IF NOT EXISTS`, or a migration tool that takes a lock.
