A <Term id="job" /> run does not start again. It fails.

## Find the kills

```bash title="Terminal"
journalctl -u ferryd | grep 'ran out of memory'
```

`ferry status NAME` and the dashboard mark a killed instance while it restarts. But Docker forgets the kill when the container runs again. Thus the <Term id="server-log" /> is the record.

## During a deploy

If a new instance runs out of memory, the deploy fails. The old instances continue to answer.

```text title="Error of the deploy" noCopy
instance ab12cd ran out of memory (limit 512 MiB) — raise the service's memory limit
```

[Resource limits](/docs/concepts/resource-limits) lists each message and how to fix it.
