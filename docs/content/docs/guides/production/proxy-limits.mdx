Ferry expects to be the edge of the server. It has no setting to trust a proxy in front of it.

## The three limits

| Limit | What to do |
|---|---|
| Ferry drops the `X-Forwarded-*`, `Forwarded` and `X-Real-IP` <Term id="header">headers</Term> that it receives. Your apps see `X-Forwarded-Proto: http`. They see the address of the reverse proxy as the client IP (`X-Forwarded-For`, `X-Real-IP`). | Some apps make absolute URLs or enforce HTTPS from these headers. Give such an app its public URL in its own configuration, for example in an environment variable. |
| The URLs that Ferry prints start with `http://`, because its own HTTPS is off. | Make the reverse proxy redirect HTTP to HTTPS. |
| Automatic HTTPS is not available. <Term id="lets-encrypt" /> must reach Ferry on port 80 of the public address, and the reverse proxy now owns this port. | The reverse proxy must hold the certificates. |
