Use this setup in two cases:

- A <Term id="reverse-proxy" /> or a cloud <Term id="load-balancer" /> has ports 80 and 443 on the server: nginx, Caddy or Traefik, for example.
- <Term id="tls" /> must stop at another place.

## Start ferryd on a local port

```bash title="Terminal"
ferryd --data-dir /var/lib/ferry \
  --base-domain apps.example.com \
  --proxy-addr 127.0.0.1:8080 \
  --public-port 80
```

In this setup, Ferry does not do HTTPS itself. Leave out `--https-addr` and `--acme-email`.

| Flag | Effect |
|---|---|
| `--proxy-addr 127.0.0.1:8080` | Only the reverse proxy can reach the Ferry proxy. No person can go around it. |
| `--public-port 80` | The port in the URLs that Ferry prints and resolves: `ferry open`, the dashboard, `${{service.NAME.url}}`. Ferry leaves port `80` out, thus the URLs are `http://<name>.apps.example.com`. |

Then [configure the reverse proxy](/docs/guides/production/nginx), and read [the limits of this setup](/docs/guides/production/proxy-limits).
