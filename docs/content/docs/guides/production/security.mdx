## Access to the server

- [ ] **Keep the API private.** Leave `--api-addr` on `127.0.0.1` and use an <Term id="ssh-tunnel" />. Or expose it only through `--dashboard-host` **with HTTPS**.
- [ ] **Create the account immediately after the first start.** Until it exists, each person who can read the setup link can create it. The link is in the server log and in `<data-dir>/setup_code`.
- [ ] **Protect the <Term id="data-directory" />.** It holds the values of variables, the passwords of datastores and the credentials in repository URLs. Limit who can log in as the user `ferry`.
- [ ] **Open only ports 22, 80 and 443.** Ferry binds the datastore ports to `127.0.0.1`, thus they are never public. Reach them over <Term id="ssh" />.

<Callout type="warning" title="Treat the password and the tokens like root passwords">
The password of the account and each <Term id="api-token" /> give full control of each app on the server.
</Callout>

Next: [tokens and secrets](/docs/guides/production/security-tokens), then [apps and servers](/docs/guides/production/security-apps).

<Accordions>
  <Accordion title="The modes of the data directory">
    Ferry creates the data directory with <Term id="file-mode" /> `0700`. It creates `api_token`, `setup_code` and `instance_id` with mode `0600`. Keep these modes.
  </Accordion>
  <Accordion title="Failed sign-ins">
    Ferry limits the failed sign-ins for the full server, not for each address. Thus a person who can reach the API can also delay your own sign-in.
  </Accordion>
</Accordions>
