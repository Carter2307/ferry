<Term id="authentication" /> is the proof of who sends a request. A `/api/v1` request has one of two proofs.

## Send a token

```bash title="Terminal"
curl -H "Authorization: Bearer $FERRY_TOKEN" http://127.0.0.1:7878/api/v1/services
```

## The two proofs

| Proof | Who uses it | How |
|---|---|---|
| An <Term id="api-token" /> | The CLI, scripts and <Term id="ci" /> | As a <Term id="bearer-token" />, in the `Authorization` header |
| The <Term id="session-cookie" /> | The dashboard | The browser gets it when you sign in with the email and the password of the account. |

The name of the cookie is `ferry_session_<port>`. The port is the port of the address that the browser uses.

See [API tokens](/docs/reference/api-overview/tokens) and [Authentication errors](/docs/reference/api-overview/auth-errors).
