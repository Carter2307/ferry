These codes come from the <Term id="git-provider" />, not from the authentication of Ferry. See [Connect GitHub or GitLab](/docs/guides/git-accounts).

## The codes

| Status | `code` | When |
|---|---|---|
| 400 | `git_application_required` | GitLab needs an <Term id="oauth-app" /> for this server before an account can authorize it. |
| 400, 409 | `git_authorization_rejected` | GitHub or GitLab refused an authorization. |
| 502 | `git_provider_unavailable` | The server cannot reach GitHub or GitLab, or the provider answered with an error. |
| 502 | `git_remote_unreachable` | The remote of a repository refused, was not there, or gave no answer in time. |

<Accordions>
  <Accordion title="git_application_required">
    Send the `client_id` and the `client_secret` of the application with `POST /api/v1/git/authorize`.
  </Accordion>
  <Accordion title="git_authorization_rejected: 400 or 409">
    - `400`: for the authorization that you make now. Examples: the provider refused a token or a code, or the user said no.
    - `409`: for the authorization that a <Term id="git-connection" /> has in the store. This authorization is no longer valid: expired, revoked, uninstalled or not complete.
    - Never `401`. This status is for the authentication of Ferry itself.
  </Accordion>
  <Accordion title="When each 502 occurs">
    - `git_provider_unavailable`: while you authorize an account, or while Ferry lists the repositories of a git connection.
    - `git_remote_unreachable`: while Ferry lists the branches of a repository (`GET /api/v1/git/branches`). The message tells why. It also tells what to do when the repository looks private.
  </Accordion>
</Accordions>
