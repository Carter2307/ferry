The streams send no event ids. Thus there is no point to continue from.

## What to do after a new connection

| Stream | Do this |
|---|---|
| [Change feed](/docs/reference/api-overview/change-feed) | Wait for `ready`. Then get your data again. |
| [Log stream](/docs/reference/api-overview/log-streams) | Read the log again. |

## What the dashboard does

- It connects again with a <Term id="backoff" /> that grows from 1 to 15 seconds.
- While the feed is down, it uses <Term id="polling" />.

In a browser, <Term id="event-source" /> connects again by itself. See [Call the API from a browser](/docs/reference/api-overview/browser).
