When a <Term id="datastore" /> exists, a <Term id="blueprint" /> changes only its <Term id="resource-limit">resource limits</Term>. Ferry changes them in place, with no restart.

## Keys that do not change it

The keys `postgresMajorVersion`, `databaseName` and `user` apply only when Ferry creates the datastore.

If one of them is different from the datastore that exists, the apply gives this warning and continues:

```text noCopy
datastores are not changed in place (ignored)
```

## The same name, the other kind

A file can ask for a Postgres datastore with the name of a Redis datastore that exists, or the opposite. This is a conflict: the apply stops with the status 409.
