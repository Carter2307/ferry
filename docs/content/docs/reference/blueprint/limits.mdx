Each <Term id="container" /> that Ferry runs gets a <Term id="memory-limit" /> and a <Term id="cpu-limit" />. This applies to each instance and each job run of a service, and to each datastore.

## The keys

| Key | Type | Default | Ferry setting and notes |
|---|---|---|---|
| `plan` | string | none | The instance type of Render. See [Plans of a service](/docs/reference/blueprint/plans) and [Plans of a datastore](/docs/reference/blueprint/datastore-plans). |
| `memoryLimit` | string or integer | none | `memory_limit_mb`, a <Term id="ferry-extension" />. It replaces the memory of the plan. |
| `cpuLimit` | string or number | none | `cpu_limit`, a Ferry key. It replaces the CPU of the plan. |

An entry can have a plan, the two keys, or all three. See [memoryLimit and cpuLimit](/docs/reference/blueprint/limit-keys).

## The server defaults

The defaults come from `ferryd --default-memory-limit` and `--default-cpu-limit`. They are 512 <Term id="mib" /> and 1 CPU unless the operator changed them. With the value 0, there is no limit. See [Server options](/docs/reference/server-options).

[Resource limits](/docs/concepts/resource-limits) explains how Ferry applies the limits.
