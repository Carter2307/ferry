## The differences

| Key or feature | On Ferry |
|---|---|
| `plan` | It becomes [resource limits](/docs/reference/blueprint/limits): the memory of the plan and, for services, its CPU. `free` gets 0.5 CPU, not the 0.1 of Render. |
| `region`, `scaling`, `previews`, `ipAllowList` and other options of the host | Ferry has no such option. It ignores them. |
| `repo` | It has no default. Render uses the repository of the blueprint itself. Ferry does not know it. |
| `image.creds` | Ferry ignores it. Ferry does not support private registries. |
| <Term id="secret-file">Secret files</Term> | Ferry does not support them. Use environment variables. |
| `port` | A <Term id="ferry-extension" />. Render has no such key. |

## Set the repository

Set `repo` on each service. Or deploy local code:

```bash title="Terminal"
ferry up NAME
```

The [Render migration guide](/docs/guides/migrate-from-render) shows a full migration.
