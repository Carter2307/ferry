Older Ferry versions ignored `plan`. After the upgrade, the first apply of a `render.yaml` that you applied before gives each entry with a `plan` its limits.

## What the first apply does

| Entry with a `plan` | Result |
|---|---|
| A live service | It restarts. |
| A datastore | Ferry changes its limits in place. |

## Before you apply

Run a <Term id="dry-run" />:

```bash title="Terminal"
ferry blueprint apply --dry-run
```

These entries show below **Would update**, with changes such as `memory_limit: (server default) → 512 MiB`.

See [Upgrade from a Ferry with no limits](/docs/concepts/resource-limits/upgrade).
