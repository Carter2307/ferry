This page lists every `ferry` command with its arguments and options. It is generated from the CLI's own help (`ferry markdown-help`), so it matches the binary built from this repository. In a terminal, `ferry <command> --help` prints the same text.

<Callout title="Connecting to a server">
Every command talks to a Ferry server. `ferry login --server URL` opens the dashboard, where you approve the terminal; it then gets an API token of its own, saved with the server in `~/.config/ferry/config.json` (`$XDG_CONFIG_HOME/ferry/config.json` when that variable is set). With `--token TOKEN`, that token is verified and saved instead. The `--server` / `--token` flags, then the `FERRY_SERVER` / `FERRY_TOKEN` variables, take precedence over the saved values. See [Set up the CLI](/docs/getting-started/cli).
</Callout>

## `ferry`

Command-line client for Ferry, a self-hosted Render alternative

**Usage**

```text
ferry [OPTIONS] <COMMAND>
```

Connection: --server/--token flags, else FERRY_SERVER/FERRY_TOKEN, else the server and token saved by 'ferry login'.

**Subcommands**

* `login` — Connect this terminal to a server and save the connection
* `info` — Show server information
* `services` — List services
* `create` — Create a service
* `show` — Show a service's settings and state
* `update` — Change a service's settings
* `delete` — Delete a service with its containers and deploy history
* `deploy` — Trigger a deploy
* `up` — Upload a local directory and deploy it (creates the service if needed)
* `deploys` — List a service's deploys, newest first
* `cancel` — Cancel a queued or in-progress deploy
* `rollback` — Roll back to a previous deploy's image
* `restart` — Redeploy the live image with the current settings and environment
* `suspend` — Stop a service's containers (the proxy answers 503)
* `resume` — Resume a suspended service
* `scale` — Set the number of instances
* `status` — Show running instances with CPU and memory usage
* `logs` — Show runtime, deploy or job logs
* `env` — List or change a service's environment variables
* `domains` — The server's domains (services are served at \<service>.\<domain>), or a service's custom domains
* `certificates` — Show the certificate of every hostname the server routes
* `run` — Run a one-off job (or trigger a cron job now)
* `jobs` — List a service's job runs, or cancel one
* `db` — Manage Postgres and Redis datastores
* `env-group` — Manage environment groups
* `blueprint` — Apply a ferry.yaml / render.yaml blueprint
* `open` — Print (and try to open) a service's URL
* `deploy-hook` — Show or rotate a service's deploy hook (a secret URL that triggers a deploy)

**Options**

| Option | Description |
|---|---|
| `--server <URL>` | Ferry API URL, e.g. http://127.0.0.1:7878 [env: FERRY_SERVER] |
| `--token <TOKEN>` | API token [env: FERRY_TOKEN] |
| `--json` | Print the raw API JSON instead of formatted output |

## `ferry login`

Connect this terminal to a server and save the connection

Without a token, opens the dashboard to approve the login there: sign in, check that the page shows the code the terminal prints, approve. The server then gives this terminal an API token of its own, which you can revoke in the dashboard. With --token (or FERRY_TOKEN), that token is verified and saved instead: for servers without a browser at hand, scripts and CI.

**Usage**

```text
ferry login [OPTIONS]
```

**Options**

| Option | Description |
|---|---|
| `--no-browser` | Only print the page to open, without opening a browser |

## `ferry create`

Create a service

**Usage**

```text
ferry create [OPTIONS] <NAME>
```

**Arguments**

| Argument | Description |
|---|---|
| `<NAME>` | Service name (lowercase letters, digits and '-') |

**Options**

| Option | Description |
|---|---|
| `-t`, `--type <TYPE>` | Service type: web, pserv, worker, cron, static |
| `--repo <URL>` | Git repository URL, or the path of a git repository on the server (a relative path that exists here is sent as an absolute path) |
| `--branch <BRANCH>` | Git branch (default: main) |
| `--image <IMAGE>` | Prebuilt Docker image |
| `--runtime <RUNTIME>` | Runtime: auto, docker, image, node, python, go, rust, ruby, static |
| `--root-dir <DIR>` | Build context subdirectory (monorepos) |
| `--dockerfile <PATH>` | Dockerfile path relative to the root dir |
| `--build-cmd <CMD>` | Build command (native runtimes) |
| `--start-cmd <CMD>` | Start command (run with sh -c) |
| `--publish-dir <DIR>` | Directory of built files to serve (static sites) |
| `--port <PORT>` | Container port the app listens on (--port 0 clears the port setting: Ferry detects it) |
| `--health <PATH>` | Health check path, e.g. /healthz |
| `--instances <N>` | Number of instances |
| `--schedule <CRON>` | Cron schedule (cron jobs), e.g. "*/5 * * * *" |
| `--disk <MOUNT>` | Mount a persistent disk at this path (limits the service to 1 instance) |
| `--domain <DOMAIN>` | Custom domain (repeatable) |
| `--memory <SIZE>` | Memory limit of each instance and job run, e.g. 512M or 1G (a plain number is MiB; 'default' = the server's default) |
| `--cpu <CPUS>` | CPU limit of each instance and job run, e.g. 0.5, 2 or 500m ('default' = the server's default) |
| `-e`, `--env <KEY=VALUE>` | Environment variable (repeatable) |
| `--env-group <GROUP>` | Link an environment group (repeatable) |
| `--no-auto-deploy` | Don't redeploy on git push |
| `--no-deploy` | Don't queue the first deploy |
| `-f`, `--follow` | Stream the first deploy's logs until it finishes (exit 1 if it fails) |

## `ferry up`

**Usage**

