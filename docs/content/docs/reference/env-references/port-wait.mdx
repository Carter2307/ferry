The properties `port`, `hostport` and `internalUrl` need the port of the referenced service. A service in its first deploy has no known port yet. This is typical when a <Term id="blueprint" /> deploys many services at the same time.

## What you see in the log

```text title="Deploy log" noCopy
==> Waiting for service 'api' to finish deploying: its port is referenced in the environment
```

## How long the deploy waits

The deploy waits 15 minutes at most. If two times the timeout of the health check is longer, it waits that long.

<Callout type="warning" title="Two services that wait for each other">
Two services can reference the port of each other before the first deploy of each. They cannot wait for each other: the deploy fails. Deploy one of them without the reference first.
</Callout>
